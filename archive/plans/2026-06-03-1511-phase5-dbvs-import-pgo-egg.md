## Context

The LTO+MMIO+Handoff pipeline (Phases 1-4) is complete but has a critical gap: the compiler cannot enforce that a Briv program's state declarations match its imported `.dbvs` schema. The `validate_schema_imports()` function exists but is only called in Verilog/VHDL paths. The LLVM path never invokes it. Additionally, `--target-dbv` is a required explicit CLI flag — the compiler should automatically detect the target from schema imports.

Two optimization passes (N3 PGO, N2 egg) are planned but need efficiency gates: they must only activate when they'll actually help, not add overhead.

## Phase 5a: DBVS Import Parsing + Schema-Aware Type Validation

### Problem
- `import "chip.dbvs"` in a `.bv` file is parsed as `TopLevel::Import` but skipped by the import resolver
- The LLVM pipeline never loads or checks the schema
- State declarations that don't match the schema silently produce wrong MMIO (or no MMIO when they should)

### Changes

#### `src/main.rs` — Wire schema import validation into LLVM path

In `run_llvm_compile()` (line ~2000), after import resolution but before type checking:

1. Scan `program.items` for `TopLevel::Import` items with `.dbvs` paths
2. Call `hardware_validator::HardwareValidator::validate_schema_imports(&program, source_path)` — this returns HW005/HW006/HW007 diagnostics for parse failures, missing files, and undeclared aliases
3. For each `.dbvs` import found, read the file, call `crate::dbriv::parse_dbvs(&content)`, and collect:
   - `schema_aliases: HashMap<String, (DbrivType, String)>` — alias name → (type, schema_path)
   - `schema_registers: HashMap<String, (DbrivAddress, DbrivType)>` — register address → type
4. Pass the schema alias map to `LlvmBackend` via a new method

#### `src/backend/llvm.rs` — Schema type cross-checking

1. Add field: `schema_aliases: HashMap<String, DbrivType>` to `LlvmBackend`
2. New method: `pub fn with_schema_aliases(mut self, aliases: HashMap<String, DbrivType>) -> Self`
3. In `generate()`, after `build_field_index()`, call `self.validate_schema_types()`:
   - For each `StateDecl` that matches a schema alias, check type compatibility
   - DBriv types mapped to Briv types:
     - `Int(n)`, `UInt(n)`, `Addr` → Briv `Int` (OK, with warning if `UInt(n)` and Briv type is `Int` — signed/unsigned mismatch)
     - `Float` → Briv `Float` (OK)
     - `Bool` → Briv `Bool` (OK)
     - `String` → Briv `String` (OK)
     - `Data` → Briv `Data` (OK)
     - `Vector(t, _)` → **error**
     - `Option(t)` → **error**
     - `Result(t, e)` → **error**
     - `Trigger(t)` → Briv `Bool` (triggers are boolean in Briv)
   - Signed/unsigned mismatch: emit warning, not error (64-bit target makes it safe)

#### `src/dbriv/ast.rs` — Add type compatibility helper

```rust
impl DbrivType {
    pub fn to_briv_type_name(&self) -> Result<&str, String> { ... }
}
```

#### `.gitignore` — Fix `*.rs` blocking pattern

Change `*.rs` to `/*.rs`. Root-level `.rs` files (generated by self-hosting/bootstrap) remain ignored. All `src/**/*.rs` are naturally tracked.

## Phase 5b: Automatic Target Resolution

### Problem
`--target-dbv zcu4ev.dbv` must be passed explicitly. The compiler should auto-detect when a schema is imported.

### Changes

#### `src/main.rs` — Auto-detect target

In the `llvm` command handler (line ~3625), after extracting schema imports:

1. For each schema import (e.g., `chip.dbvs`), search in `lib/targets/` and the source file's directory for `.dbv` files that `IMPORT` the same schema
2. If exactly one matching `.dbv` found → auto-select it
3. If zero matches → diagnostic: "no target binding found for schema chip.dbvs"
4. `--target-dbv` explicit flag always takes precedence over auto-detection

## N3: Compile-Time PGO via Interpreter (Efficiency-Gated)

### Heuristic: Branch Skew Gate

Run interpreter for `--pgo-ticks` ticks (default 10). If any guard has > `--pgo-skew`:1 ratio
(default 100:1), attach `!prof` metadata. If all guards balanced → skip. If zero guards → skip.

### Changes

- **`src/interpreter.rs`**: `profile_mode`, `branch_counts: HashMap<String, (u64, u64)>`
- **`src/analysis/pgo.rs`**: New — `has_pgo_candidate()`, `emit_branch_weights()`
- **`src/backend/llvm.rs`**: `pgo_profile` field, emit `!prof !{!"branch_weights", i32 T, i32 F}` on `br` instructions
- **`src/main.rs`**: `--pgo-generate`, `--pgo-ticks=N`, `--pgo-skew=N` flags

## N2: Equality Saturation / egg (Efficiency-Gated)

### Heuristic: Simplification Candidate Pre-Scan

Scan for: cancellation candidates (Mul/Div with constant inside Add/Sub), identity ops
(x+0, x*1), double negation (!!x), redundant comparison chains.

Gate: Skip if zero candidates or > 500 AST nodes. Apply when `optimize_budget > 0`.

### Changes

- **`Cargo.toml`**: Add `egg = "0.9"`
- **`src/analysis/equality_saturation.rs`**: New — 20-25 rewrite rules, `apply_egg()` with pre-scan
- **`src/backend/llvm.rs`**: Apply to txn body RHS expressions
