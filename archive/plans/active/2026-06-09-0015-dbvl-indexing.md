# DBVL Large-File Indexing — Phase F2 Implementation Plan

**Date:** 2026-06-09 00:15
**Status:** Approved for implementation

---

## Goal

Add key-offset index to all `.dbvl` imports. `data["key"]` seeks+parses one line instead of loading the entire file. `<:` FILTER on indexed key fields uses hash lookup automatically.

## Design

### Value::DbvlTable

New `Value` variant in `src/interpreter.rs`:
```rust
pub struct DbvlTableInner {
    pub path: String,
    pub key_offsets: HashMap<String, Vec<usize>>,
    pub field_names: Vec<String>,
    pub schema_name: Option<String>,
    pub schema_key_index: Option<usize>,
    pub cache: std::cell::RefCell<HashMap<String, Vec<Value>>>,
}
```

- `key_offsets`: key → byte offset(s) in file (supports duplicates → Vec)
- `field_names`: field names from schema, in order
- `schema_key_index`: which field index is the key (default 0)
- `cache`: parsed values, populated on demand

When `data["key"]` is accessed:
1. Check cache → return if found
2. Look up key in `key_offsets` → get byte offset(s)
3. Seek to offset in file, parse that line
4. Cache result, return

### Parser Changes

Add optional byte offset tracking to the v2 parser. When enabled, the parser records `(key, byte_offset)` for each data entry.

### Bridge Changes

For `.dbvl` files with a schema, instead of creating a `MapLiteral` with all entries, create a `__dbvl_table` call expression that the interpreter evaluates to a `Value::DbvlTable`.

## What Stays The Same

- Import syntax: `import "data.dbvl" as world`
- Access: `world.Item["key"]` — looks up, lazy parses
- `<:` FILTER: `let x <: world.Item { FILTER(.name == "val"); }` — auto-detect index
