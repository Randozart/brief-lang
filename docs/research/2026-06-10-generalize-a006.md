# Generalizing A006: Beyond Single-Txn Heuristic

**Date:** 2026-06-10T23:30:00+02:00
**Author:** Performance Investigation

## Background

The A006 fix (commit ff326e3) demonstrated that removing the `@reactor_tick`
wrapper for single-txn, no-trigger programs lets LLVM's SROA promote the
`%State` alloca to phi nodes, eliminating all GEP load/store overhead.
Result: all benchmarks with hot-loop FFI reached parity or exceeded C.

The heuristic `txns.len() == 1` was intentionally conservative. This report
investigates whether it can be generalized.

## Analysis

### emit_ssa_main already handles multiple txns

`emit_ssa_main()` iterates over ALL reactive transactions in order:

```rust
for (name, txn) in txns.iter().filter(|(_, t)| t.is_reactive) {
    self.pre_load_all_fields(out, "%state");  // loads via GEP
    // check precondition
    // execute body (stores via GEP)
    self.ssa_old_float_regs.clear();          // clear caches
    self.ssa_old_int_regs.clear();
}
```

Between txns, the `pre_load_all_fields` caches are cleared, forcing the next
txn to re-load from memory via GEP. This means:

- **Txn A stores a value via GEP** → memory is updated
- **Txn B's pre_load loads the updated value** → picks up A's change
- **Multi-txn ordering is preserved** without function call boundaries

### What blocks phi-capable codegen

The only thing preventing SROA promotion is the `@reactor_tick` wrapper
receiving `%State* %state` as a function argument. This escapes the alloca.

This is required when runtime dispatch decisions exist:
| Feature | Why reactor_tick is needed |
|---|---|
| Wake triggers | Runtime event polling — can't predict when/which |
| Enumerable triggers (some) | Switch dispatch, but each arm is its own function |
| Async/parallel dispatch | Thread pool needs independent state copies |
| MMIO addresses | Volatile semantics require special handling |

For programs with NONE of these, the dispatch is fully determined at compile
time. `emit_ssa_main` can inline all txns directly in `main()`.

### Generalized condition

```rust
!has_wake_triggers
    && enumerable.is_none()
    && self.async_txn_names.is_empty()
    && self.mmio_fields.is_empty()
```

This replaces the `txns.len() == 1` heuristic with a general predicate:
"dispatch is fully determined at compile time."

### What programs this covers

| Program type | Previously | With generalization |
|---|---|---|
| Single txn, no triggers | ✅ A006 | ✅ A006 |
| Multi-txn, no triggers | ❌ reactor_tick | ✅ A006 (new) |
| Multi-txn, enumerable triggers | Switch dispatch | Switch dispatch (unchanged) |
| Any program with wake triggers | reactor_tick | reactor_tick (unchanged) |
| Any program with async dispatch | reactor_tick | reactor_tick (unchanged) |
