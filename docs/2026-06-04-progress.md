## Bugs Fixed

### 1. DFE: FFI arguments invisible to liveness analysis

**Issue**: Kalman filter's `__print_float(energy + ei + ej)` produced no live state fields.
All 12 float fields were dead — the compiler folded the entire computation to O(1).

**Root cause**: `collect_ffi_arg_identifiers` in `transition_graph.rs` had `_ => {}`
catch-all that silently dropped `Expr::Identifier` leaf values. FFI args like
`__print_float(energy + ei + ej)` recursed through Add chains but never inserted
the leaf identifiers `energy`, `ei`, `ej` into the live seed set.

**Fix**: Changed `_ => {}` to `_ => collect_identifiers(expr, out)` in the catch-all
of the new `collect_ffi_identifiers` helper. Added `scan_for_ffi_args` that
traverses statement trees including Guarded blocks to find `Statement::Expression(Call(...))`
chains. The existing fixpoint loop then traces backward from let-bound intermediates
to state fields.

**Result**: Kalman filter now keeps all 12 float fields live through the FFI call.
The `x0 == x0` precondition self-identities (original workaround) are no longer
necessary — the FFI output IS the liveness source.

**Files**: `src/analysis/transition_graph.rs` (+90 lines)

### 2. Decreasing counter universal loop hangs

**Issue**: Programs with `rct txn [count > 0][count == 0]` and `count = count - 1`
either hung (universal loop emitted `icmp slt` which is always false for decreasing
counters) or fell back to O(N) one-tick-per-iteration path.

**Root cause**: Three separate gaps:
1. `extract_bounded_pre` only matched `Expr::Lt`/`Expr::Le` (increasing). `Gt`/`Ge` fell through.
2. `detect_increments` only matched `Expr::Add` (count = count + 1). `Expr::Sub` returned None.
3. `emit_folded_loop` unconditionally emitted `icmp slt`. No branch for decreasing direction.

**Fix** (additive changes only):
- `transition_graph.rs`: Added `ConvergeDirection { Increasing, Decreasing }` enum.
  Extended `BoundedPre` with `direction` + `bound_literal` fields. Extended
  `extract_bounded_pre` to match `Gt`/`Ge` (direction: Decreasing). Extended
  `detect_increments` to match `Expr::Sub`.
- `llvm.rs`: Added `FoldParam` struct carrying `counter_idx`, `bound_field_idx`,
  `bound_const_name`, `is_decreasing`, `bound_literal`. Threaded through all
  fold_params sites: `multi_fold_params`, `enum_fold_params`, `emit_folded_multi_main`,
  `emit_folded_loop`.
- `emit_folded_loop` header: Branched on `is_decreasing` to emit `icmp sgt` instead
  of `icmp slt`, and `bound + (unroll-1)` instead of `bound - (unroll-1)` for the
  body4 path. Added `bound_literal` priority for literal bounds like `count > 0`.

**Result**: Decreasing counter programs compile, emit `icmp sgt`, complete 50M
iterations in <10s.

**Files**: `src/analysis/transition_graph.rs` (+20 lines), `src/backend/llvm.rs` (+100 lines)

### 3. Exit expression Neg(Integer) unsupported

**Issue**: `#!exit cr >= -200` hung — exit condition never satisfied. LLVM IR showed
`add i64 0, 0 ; unsupported exit expr` instead of negation.

**Root cause**: `emit_exit_expr` early-return filter delegated `Integer`/`Bool`/`Float`
to `emit_expr`. Negative integers like `-200` are parsed as `Neg(Integer(200))` —
the `Neg` wrapper wasn't in the filter.

**Fix**: Added `Expr::Neg(_)` to the filter at `llvm.rs:3558`.

**Files**: `src/backend/llvm.rs` (1 line)
