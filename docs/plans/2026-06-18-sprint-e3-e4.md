## Sprint E3: Keys/Values Projection Stubs ✅ DONE

**What was done:**
- Added `__map_keys__` / `__map_values__` C helpers in `lib/runtime/brief_rt.c`
  - Iterates HashMap key-value pairs (flat `[data_ptr, len, k0, v0, k1, v1, ...]` layout)
  - Extracts keys (even offsets) or values (odd offsets) into a new List

- Added LLVM `declare` lines in `src/backend/llvm/emit_toplevel.rs`
- Split the combined `Keys | Values | AsStack | AsQueue` arm in `emit_expr.rs`:
  - `Keys` → `call i64 @__map_keys__(i64 %src)`
  - `Values` → `call i64 @__map_values__(i64 %src)`
  - `AsStack | AsQueue` → identity (correct — List header is compatible)

## Sprint E4: ProjectionTarget::Match — CANCELLED (Planning Error)

`ProjectionTarget::Match` was **intentionally removed** from the language.
The parser at `src/parser.rs:5719-5721` returns:

```
Match projection is no longer supported; use the `<:` operator instead
```

There is no stub to fix — Match projection was deliberately retired in
favor of the `<:` operator. The sprint plan was written based on an
incorrect assumption that a stub existed in the enum.

### What we found

| Claim in original plan | Reality |
|------------------------|---------|
| `ProjectionTarget::Match(expr)` falls through to catch-all | Variant does not exist in `ProjectionTarget` enum (src/ast.rs:411-446) |
| "Returns 0" from stub | No match arm exists because the variant was removed |
| Interpreter evaluates it | No interpreter code exists for it |

`src/ast.rs:1197` has a `Match(Box<Expr>)` in the `Pattern` enum (used
for regex/subtype matching in `.filter(x.match("pattern"))`), but this
is unrelated to `ProjectionTarget`.

### Lesson

Always verify that a variant exists in the AST enum before planning a
"stub fix." The variant table in `AGENTS.md` and the LLVM backend gap
list was out of date — it listed `ProjectionTarget::Match` as a stub
but the variant had already been removed. This has been corrected:
the gap list now correctly notes this is not a gap.
