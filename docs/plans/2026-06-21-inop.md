# `inop#` — User-Defined Intrinsic Operations (2026-06-21)

The `inop`/`inop!` keyword represents the safe, syntactically explicit "airlock"
between high-level Brief semantics and **BILD** (Brief's Inop LLVM Dialect) —
a subset of LLVM IR with Brief-flavored syntax. It allows the standard library
and systems programmers to implement high-performance low-level primitives
without modifying compiler source code.

**2026-06-22 update:** The body language is now formally named **BILD**
(Brief's Inop LLVM Dialect). See `docs/architecture/features/bild.md` for
the dialect reference and `learn-brief/14-bild.md` for the tutorial.

## Declaration

| Keyword | `has_side_effects()` | Semantics |
|---------|---------------------|-----------|
| `inop` / `inop#` | `false` | Pure — eligible for CSE, DCE, precomputation |
| `inop!` / `inop#!` | `true` | Side-effecting — not reorderable/eliminable |

The `#` on the keyword is cosmetic — `inop` and `inop#` parse identically.
`inop!` and `inop#!` likewise.

### Syntax

```brief
// Pure: inop / inop#
inop sadd(a: Int, b: Int) -> Int [pre: a + b <= 9223372036854775807] {
    %res = add i64 %a, %b
    term %res
} fallback { a + b }

// Side-effecting: inop! / inop#!
inop! write_buf(ptr: Ptr<Byte>, len: Int) -> Int {
    %res = call i32 @write(i32 1, i8* %ptr, i64 %len)
    term %res
} fallback { 0 }
```

The BILD body uses `;` as a statement separator and `term`/`term!` as the
unified terminator. Newlines are lexer whitespace.

The `fallback expr` (no braces) is optional but strongly recommended. Without it,
the interpreter cannot execute the intrinsic, the proof engine cannot verify
contracts, and non-LLVM backends cannot compile.

### Parameter mapping (BILD types)

Brief parameter names map directly to LLVM SSA names with their native types.
See `docs/architecture/features/bild.md` for the full type mapping table:

| Brief type | LLVM type | Example |
|------------|-----------|---------|
| `Int` | `i64` | `%x` |
| `Float` | `float` | `%f` |
| `Bool` | `i8` | `%b` |
| `Char` | `i32` | `%c` |
| `String` / `Data` | `i8*` | `%s` |

### `term` lowering

The `term` keyword inside the LLVM IR body is transformed by the backend:

| Context | Lowering |
|---------|----------|
| Standalone function | `term %res` → `ret i64 %res` |
| Callable txn | `term %res` → `store i64 %res, %result; br %post_label` |
| Reactive txn | `term!` → `br %done` |

## Call Site

All `inop`/`inop!` intrinsics are called via the existing `identifier#(args)`
syntax — identical to built-in intrinsics:

```brief
let r = sadd#(x, y);
let n = write_buf#(ptr, len);
```

The call uses the existing parser path at `parser.rs:6142-6174` (`identifier #
( args )` → `Expr::IntrinsicCall`). The parser checks `Intrinsic::from_name(name)`
first, then falls back to the program's `inop_decls` map.

## Boundary Rules

| Rule | Detail |
|------|--------|
| No state access | `%state` pointer not available — explicit params only |
| Single output | Phase 1: exactly one return type |
| No recursion guard | Structural recursion checker operates on fallback only |
| Param type mapping | Body receives native LLVM types via param name (not positional `%argN`) |
| Safety | Malformed LLVM IR is a `llc` compile-time error — the user's test suite catches it |
| Backend coupling | LLVM-only; non-LLVM backends use fallback or fail |
| Intrinsic enum | `UserDefined(String)` is a single additive variant; no existing code modified |

## Reasonable to Ship Without

- **SMT-LIB translation**: LLVM IR → SMT-LIB bvlogic translator is Phase 3.
  Phase 1 uses the fallback expression for contract verification.
- **Polyglot bodies**: Webstack/CIRCT targets use the fallback expression.
  Multi-backend IR bodies can be added in Phase 2 if users need them.
- **`?#` watchdog integration**: The proof oracles exist but wiring `?#` to
  substitute fallback paths for unprovable `inop#` bodies is Phase 2.
- **Precomputation of `inop#` calls**: `inop` bodies are LLVM IR, not AST.
  Precomputation works on the fallback expression (if present) or is blocked.
