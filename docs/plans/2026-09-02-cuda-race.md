## Phase A — the anchor (no baseline, no campaign)

`benchmarks/gpu/ggml_gemm_bench.c` — bare `ggml_mul_mat` f16 4096³ via
VITRIOL's CUDA backend (GGML_CUDA, archs 61;86), same box, locked clocks
(nvidia-smi -pm 1 -lgc 1800,1837 — ACTIVE), sync-per-iter (the Vulkan
anchor's convention). Ledger row becomes the race target. If the CUDA
build has friction: record it, fall back to llama.cpp's non-cuBLAS MMA
path (still the honest llama.cpp CUDA number).

## Phase B — the tensor-tier campaign (rung → A/B → ledger row)

1. **smem A-panel reuse** (recorded, never run): A panel staged in shared
   memory across the R warp fragments. B traffic is already ÷R (R=4).
2. **occupancy reshape**: 16k workgroups × 32 lanes underfills 28 SMs —
   fewer/fatter workgroups (64-128 lanes, multiple fragment pairs),
   config knob `spirv_coopmat_groups` (tile_rows pattern).
3. **FP16-acc tier** (`spirv_coopmat_f16acc`, SEPARATE numerics tier):
   accumulator coopmat<f16> → 2× MMA ceiling. Contract: gate rel ≤ 1e-2
   vs the f32-acc tier (default + correctness reference). Runtime probe:
   coopmat fp16-acc support; unsupported → VERDICT, move on.
4. **split-K** for skinny M (decode shapes M=1-32): K-split across
   workgroups + reduction pass.
5. stretch: persistent kernels / L2 residency.
