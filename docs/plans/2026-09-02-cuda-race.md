## B2 session addendum (2026-09-02, later)

**B2 occupancy reshape LANDED** (`spirv_coopmat_subgroups`, 1-4): S
subgroups per tensor workgroup, each owning its tile_n slice — the
decode derives SubgroupId from gl_LocalInvocationID (y*4 + x/32; NVVM
rejected the SubgroupId builtin outright, and LocalInvocationIndex is
i64 in this module so UDiv is ill-typed — the v3uint decomposition is
exact on every 32-lane target). LocalSize = 32*S; dispatch geometry is
S-invariant (M·N/32R items — the driver divides by the blob's
LocalSize).

**A/B (f16acc ON, 4096³, locked clocks, 131072 items):**
- S=1: min 7.022ms = **16.6 TFLOP/s** (best)
- S=4: min 7.220ms — neutral
- VERDICT: subgroups don't move this shape on this driver — the
  32-lane-workgroup underfill theory was wrong (occupancy was never
  the bottleneck; the coopmat mma throughput + K-loop latency is).

**Best measured: f16-acc S=1 = 7.022ms = 16.6 TFLOP/s.** vs the CUDA
anchor 42.0: 2.5× remains. The ledger's next rung (B1 smem A-panel
reuse) and their real edge (async-copy multi-stage pipelines at
128×128 tiles) are the remaining fight.

En-route lesson (recorded): three successive "failures" were STALE
BINARIES — the 0.1-0.5s cargo "Finished" lines after source edits were
fingerprint no-ops. `touch` + watch for a real compile (≥2min) before
trusting an A/B.

## B1 session addendum (2026-09-02, latest) — VERDICT: REJECTED

**B1 double-buffered K loop** (software pipeline: panel k+1 loads issued
in the body via pre-reserved fragment-phi back-edges while the mma
consumes panel k through phis; preheader loads panel 0; the final
prefetch clamps to the last panel):

**A/B (f16-acc, S=1, 4096³, locked clocks, interleaved rounds):**
- straight-line (pre-B1): min 7.130 / 7.158ms
- double-buffered: min 7.736 / 7.782 / 7.832 / 7.842ms

**~9% SLOWER.** The 8 per-iteration CopyObject back-edge writes + the
clamp Select cost more than the overlap saves — NVIDIA's own compiler
already software-pipelines the straight-line load→mma pattern (the
coopmat load queue depths absorb DRAM latency). Code reverted; the
mechanism + measurements are the record. If async-copy lands in the
Vulkan dialect properly (VK_KHR_cooperative_matrix + shared staging),
revisit — but that is the "their real edge" rung, not this workaround.

Race state after B1/B2/B3: **16.6 TFLOP/s best (f16-acc S=1)** vs CUDA
42.0 — the remaining 2.5× is pipeline depth + tile size, both requiring
the shared-memory staging rung done PROPERLY (smem-staged A/B panels
with explicit multi-stage control), not register prefetch.

## B1' addendum — the smem-staging SPEC constraint (2026-09-02, latest)

Attempted the coopmat-variable form: Workgroup-storage `coopmat<f16>`
variables as the pipeline stages. **SPIR-V spec wall**: "Cooperative
matrix types (or types containing them) can only be allocated in
Function or Private storage classes or as function parameters" —
Workgroup coopmat variables are ILLEGAL (spirv-val caught it; emission
reverted).

**The correct design (next session, scoped):**
1. Stage RAW f16 halves in Workgroup ARRAYS (plain shared memory — the
   tiled f32 tier already emits these; reuse its ArrayStride/Block
   machinery). Per stage: R×256 (A) + 4×256 (B) halves = 4KB/stage,
   8KB both — fits trivially.
2. Fill: scalar/vec4 strided copies DRAM→smem, 64 halves per lane per
   iteration (the classical pattern; the tiled tier's copy loop is the
   precedent).
3. Consume: `OpCooperativeMatrixLoadKHR` from a Workgroup-storage
   ELEMENT pointer into the shared array (stride 16) — Workgroup
   pointers as LOAD SOURCES are the spec-legal form.
4. Pipeline: prologue fills stages 0+1 → barrier; body = coopmat loads
   from stage k%2 → mma → barrier → fill stage k%2 with panel k+2
   (clamped). One barrier per iteration; fence-ordering semantics
   AcquireRelease|WorkgroupMemory (0x43).
5. Everything else from this session's attempt carries over: the parity
   selector (kt_u & 1), the runtime pointer/array indexing lessons
   (never index Rust vectors by runtime ids), the module-level variable
   placement rule.

Race state unchanged: **16.6 TFLOP/s best vs CUDA 42.0.**
