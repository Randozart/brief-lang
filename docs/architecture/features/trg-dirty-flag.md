# trg Reactive Dirty-Flag System

## Purpose
Replace the old polling-based trigger system (`__trg_stdin_read`, `__trg_timerfd_read`, `__trg_signalfd_read`) with a compile-time dependency graph + bitmask dirty-flag architecture. Each `trg` declaration becomes an externally-driven input; dependent state variables are recomputed in topological order when any trigger fires.

## Syntax
```briv
trg sensor: Int @ 0x1000;       // MMIO-mapped sensor input
trg keypress: Char @stdin;      // stdin event (epoll-driven)
trg tick: Int @timer(60);       // 60 Hz periodic timer
```

### `wake` Default

All triggers are now **wake by default** — the reactor blocks on epoll (for built-in sources) or `__rt_wait()` (for MMIO-only programs) rather than busy-looping.

Use `#nowake` for passive triggers that should be read-only (e.g., an MMIO input that doesn't need to drive the tick loop):

```briv
trg io_pending: Bool @ link __io_pending;    // wake (default) — blocks until __io_pending changes
trg button: Bool @ 0x5000 #nowake;            // passive — polled but doesn't wake the reactor
```

A `#nowake` trigger is still sampled every tick (its value is loaded from the state), but the reactor will not block waiting for it to fire. This is useful for read-only sensors that are polled on demand.

## Architecture — Three Backend Patterns

The dirty-flag system adapts to each backend's execution model:

| Backend | trg semantics | Dirty-flag mechanism |
|---------|---------------|---------------------|
| **LLVM** | `volatile` load | u64 bitmask → `step(%State*, i64)` function |
| **Webstack** | Reactive signal | `dirty_signals: Vec<bool>` in generated Rust |
| **CIRCT** | HW input port | Purely combinatorial — no step function needed |

## Dependency Graph (Phase 1)

`src/analysis/dependency_graph.rs` provides the compile-time dependency analysis:

```
Topological sort (Kahn's algorithm):
  trg a → [bit 0]
  trg b → [bit 1]
  state c = a + b → [bit 2]  depends on a, b
  state d = c * 2 → [bit 3]  depends on c

Step order: a, b, c, d
Dirty check: if bit 0 or bit 1 set → recompute c
             if bit 2 set → recompute d
```

### Data structures
```
DependencyGraph
  topo_order: Vec<String>       — variables in evaluation order
  bit_index: HashMap<String,usize> — bit position per variable
  dependencies: HashMap<String,Vec<String>> — var → its inputs
  dependents: HashMap<String,Vec<String>>  — reverse map
  is_trg: HashSet<String>       — externally-driven variables
  all_vars: HashSet<String>     — all known state/trigger vars
```

### Cycle detection
Kahn's algorithm detects cycles. A cyclic dependency graph returns
`DependencyError { cycle: Vec<String> }`. In hardware (CIRCT), cycles
would cause combinational loops — the graph must be acyclic.

## DirtyFlags Bitmask (Phase 2)

`DirtyFlags(u64)` in `src/backend/mod.rs`:

- `mark(idx)` — set bit `idx`
- `is_set(idx)` — test bit `idx`
- `clear(idx)` — clear bit `idx`
- `mark_downstream(&[idx])` — set all downstream bits
- `merge(&other)` — bitwise OR
- `any()` / `none()` — any flags set?
- `bits()` — raw mask

## LLVM step() Function (Phase 3)

Generated by `emit_trg_step()` in `loop_engine.rs`:

```llvm
define void @step(%State* noalias nocapture %state, i64 %dirty_in) {
  entry:
    %dirty = alloca i64, align 8
    store i64 %dirty_in, i64* %dirty
    ; volatile-load all triggers (liveness anchor)
    %gtrg_sensor = getelementptr %State, %State* %state, i32 0, i32 0
    %ltrg_sensor = load volatile i64, i64* %gtrg_sensor
    store volatile i64 %ltrg_sensor, i64* %gtrg_sensor
    ; for each computed variable, check dirty flags
    %ld = load i64, i64* %dirty
    %and = and i64 %ld, 2    ; check bit 1
    %cmp = icmp ne i64 %and, 0
    br i1 %cmp, label %step_body_c, label %step_skip_c
  step_body_c:
    ; recompute c from a, b
    ...
    br label %step_skip_c
  step_skip_c:
    store i64 0, i64* %dirty  ; clear all flags
    ret void
}
```

### Event loop (future)
The main loop will use epoll instead of `__rt_wait()`:
1. `epoll_create1(0)` — create epoll instance
2. `epoll_ctl` — register trigger FDs (timerfd, signalfd, stdin)
3. `epoll_wait` — block until event
4. Mark dirty bits for fired triggers
5. Call `step(%state, dirty_flags)`
6. Check exit condition, loop

## CIRCT Backend (Phase 4)

`src/backend/circt.rs` emits MLIR text in **HW + Comb + Seq** dialects.
trg variables become top-level input ports; computed variables become
output ports or internal wires.

```mlir
hw.module @top(clock: i1, reset: i1, sensor: i64, c: i64) -> () {
  %c0_c = hw.constant 0 : i64
  hw.output_assign c, %sensor : i64
  hw.output
}
```

No dirty-bit step() function — hardware is purely combinatorial. The
dependency graph verifies acyclic connectivity before MLIR emission.

## Webstack Integration (Phase 5)

`TopLevel::Trigger` declarations are registered as signals in the
existing `collect_signals_and_transactions`. A `step_triggers()` function
is generated in the Rust output:

```rust
pub fn step_triggers(&mut self) {
    // trigger 'sensor' (signal 0) — mark dirty for re-evaluation
    self.dirty_signals[0] = true;
    self.dirty_transactions[0] = true;  // mark dependent txn
}
```

## Cleanup (Phase 6)

Removed `__trg_stdin_read()` polling function from `briv_rt.c` and
its `declare` in the LLVM backend. The remaining timerfd/signalfd
polling functions (`__trg_timerfd_open/read`, `__trg_signalfd_open/read`)
are deprecated and will be removed once the epoll event loop is fully
integrated into all main-loop dispatch paths.
