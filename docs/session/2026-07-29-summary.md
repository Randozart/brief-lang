# Session Summary — 2026-07-29

## Verification Chain Architecture

Replaces the "derivation-only" model with a general **compile-time
cross-verified implementation selection** mechanism. The `:=` operator
declares a chain of structurally equivalent implementations; the compiler
selects the first one whose target matches and passes cross-verification.

### Architecture

```
defn popcount(x: Int) -> Int := asm_popcnt := asm_arm := popcount_ref;
                                  ^           ^          ^
                                  |           |          └── unguarded fallback
                                  |           └── cross-verified against ref
                                  └── cross-verified against ref
```

Chain resolution at compile time:
1. Filter bodies by target (asm<target> must match compile target)
2. For each candidate in order: evaluate against every other body on
   N random inputs (default 50, from --verify-samples)
3. If all outputs match → select this body
4. If any mismatch → skip to next body
5. Fall through: last body is always accepted (the reference)

### Key behaviors

- **`asm<target> fn ... { "..." }`** — parsed, typechecked, registered
  as a callable function, emitted as `call asm sideeffect` in LLVM IR
- **Direct calls** work: `popcnt_asm(x)` from any defn body
- **Cross-verification**: asm is compiled via gcc→.so→libloading at
  compile time, called with test inputs, outputs compared with reference
- **No trust required**: if asm produces wrong output for any test input,
  the compiler skips it. Last body (reference) is always accepted.
- **Param name mapping**: reference functions can use different param
  names (e.g., `x`) than the derivation block (e.g., `x0`); binding
  is by position

### End-to-end verified

```briv
asm<x86_64> popcnt_asm(x: Int) -> Int { "popcnt {result}, {x}" };
defn popcount_ref(x: Int) -> Int { <parallel prefix formula> };
defn f(x: Int) -> Int := popcnt_asm := popcount_ref;

// At compile time:
//   popcnt_asm compiled → popcnt(-165) = 61
//   popcount_ref evaluated → popcount_ref(-165) = 61
//   Match → popcnt_asm selected
//   LLVM emits: define i64 @popcnt_asm(i64 %rdi) {
//     %r = call i64 asm "popcnt $0,$1", "=r,r,..."(i64 %rdi)
//     ret i64 %r
//   }
```

## Deferred items

### Verification chain improvements

| Item | Why deferred | Effort |
|------|-------------|--------|
| **Keystone integration** | `keystone-sys` adds a C library dependency. Platform assembler (`as`) works for now. Add as `assembler = "keystone"` handler in `get_assembler()`. | ~50 lines FFI + Cargo dep |
| **Formal SMT asm verification** | Translate the compiled asm bytes to SMT semantics and verify against the reference via Z3. Would give mathematical certainty over all inputs (not just random samples). Requires extracting asm semantics from LLVM MC layer. | Large research effort |
| **Performance selection** | Currently first-matching body wins. The plan describes benchmarking each candidate and selecting the fastest. Needs compile-time benchmarking infrastructure. | ~200 lines |
| **Wasm asm target** | Webstack backend for `asm<wasm32>` is not implemented (wasm has no inline asm concept). | Unknown |

### Asm function improvements

| Item | Why deferred | Effort |
|------|-------------|--------|
| **FFI safety** | `evaluate_asm` uses `unsafe` FFI. A borrow-checked or sandboxed approach would be safer for compile-time execution of arbitrary asm. | ~100 lines |
| **Multi-arch JIT cache** | Currently recompiles the asm for every cross-verification sample. A JIT cache (compile once, call many times) would be ~50x faster. | ~80 lines |
| **GCC/clang detection** | The asm compiler is hardcoded to `gcc` with `CC` env override. Detection of `clang` as fallback would improve portability. | ~30 lines |
| **Multi-instruction asm** | The LLVM `emit_asm_fn` handles multi-instruction bodies. The `evaluate_asm` compile-time test wraps all instructions in a single asm block (no register liveness between them). Proper multi-instruction evaluation requires register allocation or single-instruction-per-sample. | ~100 lines |
| **ABI register mapping table** | Currently hardcoded for x86_64 and aarch64. A config-driven table (in `config/` TOML) would support more architectures without compiler changes. | ~100 lines + config |

### Derivation system improvements

| Item | Why deferred | Effort |
|------|-------------|--------|
| **Counterexample injection → Z3** | `smt_verify_candidate` has `let ref_fn = None` (the Z3 path ignores the reference function when verifying). The random verification path (for no-postcondition) already injects counterexamples correctly. Z3 path needs `ref_fn` threaded through `build_verification_query`. | ~30 lines |
| **Caching for anti-unification** | Pairs of LevelCache expressions are anti-unified from scratch each depth level. Caching pairs that were already checked would save repeated work. | ~60 lines |
| **Adaptive helper discovery** | The threshold for helper extraction (`min_savings >= 1`) is fixed. Adaptive thresholds based on LevelCache growth rate would be more robust. | ~40 lines |
| **LUT compilation flag** | "Turn derivation bodies into LUTs" — compile example-only derivation blocks as switch tables instead of ite chains. Controlled by `--derive-lut` flag. | ~200 lines |
| **Popcount needs depth 12** | The parallel prefix popcount formula fundamentally requires depth ~12. No amount of CEGIS at depth 4-5 can produce it. The verification chain's fallback to `popcount_ref` handles this: the reference IS the implementation. | Stretch goal |
| **Cross-depth propagation** | Currently, the chain resolver only works with bodies available at a single depth. Cross-depth resolution (try synthesis at depth 3, 4, 5 in sequence) is not implemented. | ~80 lines |

### Platform support

| Item | Why deferred | Effort |
|------|-------------|--------|
| **Windows platform assembler** | `PlatformAssembler` uses `as` (Unix). Windows uses `ml64` (MASM) with different syntax. | ~50 lines |
| **libloading without asm** | The `evaluate_asm` function uses `libloading` (already in Cargo.toml). On platforms without `gcc` or `as`, evaluation falls through to cross-verification failure, skipping the asm body. No crash. | 0 — works by fallback |
