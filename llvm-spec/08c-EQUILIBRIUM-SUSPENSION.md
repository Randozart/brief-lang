# Equilibrium Suspension: Replacing Busy-Spin with Event-Driven Sleep

## 1. The Problem: 100% CPU Busy-Spin

In the current reactor loop (`08-REACTOR-LOOP.md`), when no transaction preconditions are met, the `noop` path branches straight to `commit`:

```llvm
noop:
    br label %commit
```

On an OS target, this compiles to an infinite loop that spins at **100% CPU core utilization**, draining battery and generating heat even when the system is completely idle.

## 2. The Solution: `__wait_for_event()`

Replace the `noop → commit` path with a blocking suspension call:

```llvm
noop:
    call void @__wait_for_event()
    ret void
```

**The rule:** If no transaction's precondition evaluates to true, the system is in **equilibrium**. There is no work to do. The reactor suspends until an external event (a trigger mutation, a timer, an interrupt) upsets the equilibrium.

## 3. Resolution via Bootstrap Intrinsic

`__wait_for_event()` is registered as a **bootstrap intrinsic** in the existing FFI Dictionary — the same mechanism used for `__print`, `__read_file`, `__exit`. No new mechanism is introduced.

### Per-Target Lowering

| Target | Instruction | Effect |
|--------|-------------|--------|
| Linux (epoll) | `epoll_wait(epfd, events, maxevents, -1)` | OS suspends thread — **0% CPU**. Wakes on any registered fd event (bound to a `trg`) |
| Linux (select) | `select(nfds, &rfds, NULL, NULL, NULL)` | Portable fallback if epoll unavailable |
| ARM Cortex-M | `wfi` (Wait For Interrupt) | CPU halts pipeline, microwatt sleep. Wakes on hardware IRQ |
| RISC-V | `wfi` | Same — architecture-defined sleep until interrupt |
| WebAssembly | Asyncify yield | Returns to browser event loop via stack-swapping. Browser remains responsive |
| Bare-metal (x86) | `hlt` + `sti` | Halts CPU until next interrupt. `sti` re-enables interrupts |

### Trigger → Event Mask Synthesis

The compiler analyzes the program's `trg` declarations (`08a-TRIGGERS.md`) to determine which events can wake the system:

- **MMIO triggers:** No OS event — `__wait_for_event()` on bare-metal uses `wfi`/`hlt` (any interrupt wakes the CPU, and the tick re-evaluates)
- **FFI-poll triggers:** The `__poll_triggers()` call (already inserted before `reactor_tick()` on OS targets) updates shared memory; `__wait_for_event()` uses `epoll_wait` on the underlying fd
- **Metropolitan triggers:** Spinlock + `pause` — the yielding thread polls the status word with a hardware pause (prevents overheating while waiting for IPC)

For the epoll case, the compiler generates a `pollfd` array from the trigger map at compile time:

```c
// Generated by compiler for Linux target:
struct epoll_event events[TRG_COUNT];
// Each trg's underlying fd is registered with epoll during init_state()
```

## 4. Integration Points

### `main()` function
```llvm
define i32 @main() local_unnamed_addr #0 {
entry:
    call void @init_state()
    call void @__register_triggers()  ; Register all trg fds with epoll
    br label %tick
tick:
    call void @reactor_tick()
    br label %tick
}
```

### `reactor_tick()` — equilibrium path
```llvm
noop:
    call void @__wait_for_event()  ; Suspend until event
    ret void
```

### Trigger synthesis note
When `__wait_for_event()` returns, the reactor loop re-enters `reactor_tick()`. The trigger sampling phase at tick entry (`08a-TRIGGERS.md`) reloads all volatile `trg` values — so the sampled data is always fresh from the event that woke the system.

## 5. Safety: No Missed Events

Because `__wait_for_event()` is called only on the `noop` path (after ALL preconditions have been evaluated and found false), there is no risk of missing a trigger that fires during evaluation. The trigger sampling phase runs before precondition evaluation, and if any precondition were true, we'd never reach `noop`.

Edge case: A trigger fires BETWEEN the sample phase and `__wait_for_event()`. This is safe — the next tick will sample it. Reactor semantics guarantee eventual processing, not immediate processing.
